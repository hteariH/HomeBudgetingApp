# План: Android-приложение «PersonalMoney» — учёт личных финансов

## Контекст

Локальное Android-приложение для учёта личных финансов. Главная ценность — максимально удобное и быстрое внесение расходов (включая виджет на главный экран). Бэкенда нет, всё хранится локально. Монетизация — через рекламу AdMob.

Подтверждённые решения:
- **Стек:** Kotlin + Jetpack Compose + Material 3 + Glance (виджеты)
- **Min SDK:** 26 (Android 8.0), Target SDK: 35
- **Курсы валют:** ручной ввод + Frankfurter **v2** API (`api.frankfurter.dev/v2/rates`, ~165 валют вкл. UAH/RUB, бесплатно, без ключа) с локальным кэшем
- **Языки:** Русский, Английский, Украинский

Общий объём: **~70 ч** работы (~3 календарных недели по 4-5 ч в день).

**Доработки сверх первоначального плана (текущая работа):**
- **Переводы** интегрированы как 3-й режим экрана быстрого ввода (Расход / Доход / **Перевод**),
  отдельный экран перевода больше не нужен. Кросс-валютные переводы авто-конвертируют сумму
  получателя по курсу (с правкой вручную); подсказка курса под суммой.
- **FX мигрирован с Frankfurter v1 → v2** (`api.frankfurter.app` → `api.frankfurter.dev`): v1 —
  только ~30 валют ЕЦБ без UAH/RUB; v2 — ~165 валют. Эндпоинт `v2/rates`, параметр `quotes`,
  ответ-массив. Курсы обновляются и при запуске (`FxScheduler.refreshNow()`), не только раз в сутки.
- **Экран транзакций:** фильтр по счетам; переводы показываются одной строкой «откуда → куда»
  (пара debit/credit схлопывается) с двумя суммами для кросс-валюты; фильтры período/тип/счёт —
  компактными дропдаунами в одну строку.
- **Навигация:** нижний таб-бар + FAB; полноэкранный выбор счёта.

**Осталось до релиза:** keystore + release-сборка с боевыми AdMob ID, хостинг Privacy Policy,
форма Data Safety в Play Console. (Иконка, feature graphic и скриншоты уже готовы.)

## Архитектура

```
app/
├── core/
│   ├── database/        # Room: entities, DAOs, migrations
│   ├── domain/          # модели, use-cases, валидация
│   ├── data/            # репозитории, маппинг entity↔domain
│   ├── ui/              # тема Material3, общие composables
│   ├── currency/        # FX-курсы, конвертация
│   └── notifications/   # WorkManager, AlarmManager для подписок
├── feature/
│   ├── quickadd/        # быстрый ввод расхода (главный экран ввода)
│   ├── dashboard/       # сводка, графики, недавние операции
│   ├── transactions/    # история, фильтры, поиск
│   ├── accounts/        # CRUD счетов
│   ├── categories/      # CRUD категорий доходов/расходов
│   ├── transfers/       # переводы между своими счетами
│   ├── subscriptions/   # рекуррентные подписки
│   ├── settings/        # настройки, бэкап, валюты
│   └── onboarding/      # первый запуск
├── widget/              # Glance-виджет быстрого расхода
└── ads/                 # AdMob + UMP consent
```

**Принципы:**
- ViewModel(StateFlow) → Compose (однонаправленный поток)
- Hilt для DI
- Room + Flow для реактивных запросов
- Деньги хранятся как `Long` минорных единиц
- `kotlinx.serialization` для бэкапа/импорта JSON

## Риски

- **AdMob + Privacy Policy** — обязательны для Play. URL приватности — на вас.
- **Frankfurter API** — fallback на ручные курсы и кэш 30 дней.
- **Glance Widget на API 26–28** — особенности RemoteViews, +1 ч на адаптацию.
- **Валюты с разным числом знаков** (JPY=0, BHD=3) — берём из ICU.

## Что изменилось после плана

- **Облачная синхронизация — сделана.** Приложение стало клиентом сервера HomeBudgeting:
  `core/auth` + `core/network` + `core/sync`. «Локально-первым» оно быть не перестало —
  данные по-прежнему живут в Room и работают без сети, но сходятся на сервере.
- **Биометрический lock — сделан** (`core/security/BiometricGate`).
- **Импорт выписок — сделан на сервере** (CSV и Monobank), клиенту остаётся UI.
- **iOS и web — теперь цель, а не исключение.** Репозиторий переезжает на Kotlin Multiplatform
  (Compose Multiplatform · Ktor · Room KMP · Koin · RevenueCat), чтобы один код обслуживал
  Android, iOS и веб. Веб заменит нынешний React-фронтенд в `../HomeBudgetingApp`.
